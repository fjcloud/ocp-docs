You can enable optional Kubernetes metric exporters on MicroShift to expose metrics that are compatible with OpenShift Container Platform monitoring dashboards and alerting rules.

Enhanced metrics in MicroShift

Enhanced metrics in MicroShift are optional Kubernetes metric exporters that expose Prometheus-compatible endpoints through cluster Services. You can install each exporter individually to align edge monitoring with metrics used in Red Hat build of MicroShift clusters.

MicroShift does not deploy the full Cluster Monitoring Operator (CMO) stack, such as Prometheus or Alertmanager. Instead, enhanced metrics reuse OpenShift-built container images for the following optional components:

node-exporter

Exposes hardware and operating system metrics, such as CPU, memory, disk, and network utilization.

metrics-server

Provides the Kubernetes resource metrics API so that you can run oc adm top nodes and oc adm top pods.

kube-state-metrics

Exposes metrics about the state of Kubernetes API objects, such as deployments, pods, and nodes.

External tools, such as a locally running OpenTelemetry Collector or a remote Prometheus database, can scrape the exporter endpoints after you install the corresponding RPM packages.

Installing enhanced metrics packages is independent of installing the microshift-observability RPM. You can use enhanced metrics without deploying the OpenTelemetry Collector, and you can install observability without installing any enhanced metrics exporters.

Enable enhanced metrics in MicroShift

Install one or more optional metrics RPM packages and restart MicroShift to deploy the exporters that your monitoring workflow requires.

Prerequisites

  • MicroShift is installed and running.

  • You have root access to the MicroShift host.

  • The OpenShift CLI (oc) is installed.

Procedure

  1. Install the RPM packages for the exporters that you want to enable.

    Install only the exporters that your monitoring workflow requires. You can enable the exporters in any combination.

    For example, to install node-exporter and metrics-server, run the following command:

    $ sudo dnf install -y microshift-metrics-node-exporter microshift-metrics-server

  2. Restart MicroShift to deploy the installed exporters by running the following command:

    $ sudo systemctl restart microshift

  3. Verify that the exporter pods are running in the openshift-monitoring namespace by running the following command:

    $ oc get pods -n openshift-monitoring

    When node-exporter is enabled, the output includes a node-exporter pod on each node. When metrics-server or kube-state-metrics is enabled, the output includes the corresponding deployment pods.

  4. Verify that the metrics Services are available by running the following command:

    $ oc get svc -n openshift-monitoring

  5. If you installed metrics-server, verify that resource metrics are available by running the following commands:

    $ oc wait apiservice/v1beta1.metrics.k8s.io \
  --for=condition=Available --timeout=120s
$ oc adm top nodes
$ oc adm top pods -A

Example: Collecting enhanced metrics with MicroShift Observability

When you install both enhanced metrics RPM packages and the microshift-observability RPM, the OpenTelemetry Collector automatically scrapes the enabled exporter endpoints and forwards the metrics to your configured back end.

Prerequisites

  • You installed and configured MicroShift Observability.

  • You installed one or more optional metrics RPM packages and restarted MicroShift to deploy the exporters that your monitoring workflow requires.

Procedure

  1. Confirm that the OpenTelemetry Collector service is running by entering the following command:

    $ sudo systemctl status microshift-observability

  2. Inspect the collector logs to verify that metrics are being scraped by entering the following command:

    $ sudo journalctl -u microshift-observability

    When kube-state-metrics is enabled, the logs can include successful scrapes of the kube-state-metrics Service endpoints. When node-exporter is enabled, the logs can include successful scrapes of the local node-exporter endpoint.

  3. Verify that metrics are forwarded to your configured OpenTelemetry Protocol (OTLP) endpoint by checking the back end that receives data from the collector.

Enhanced metrics security considerations

When you enable enhanced metrics in MicroShift, you expose additional endpoints that can reveal information about the host, node objects, and resource usage. Review the following considerations before installing exporters and before configuring external scrapers or monitoring back ends.

Sensitive information in metrics

Exported metrics can reveal host configuration, Kubernetes object metadata, and resource usage patterns. MicroShift applies a default metric denylist for kube-state-metrics to reduce exposure of secret and annotation data, but metrics can still include object names, labels, and state information that describe your workloads.

Authentication and authorization

node-exporter and kube-state-metrics

The exporters listen on localhost inside their pods. Their kube-rbac-proxy sidecars expose HTTPS /metrics endpoints. Scrapers must present a client certificate trusted by the metrics-client-ca bundle. The proxies use a static rule for GET /metrics but do not perform a Kubernetes SubjectAccessReview for these requests. A service account token or role-based access control (RBAC) grant by itself does not allow scraping.

metrics-server resource metrics API

The aggregated [metrics.k8s.io](http://metrics.k8s.io/) API provides node and pod resource usage. Kubernetes RBAC controls access to this API.

metrics-server resource /metrics endpoint

This endpoint exposes the metrics of the metrics-server, but not node and pod resource usage. Access requires GET permission for the /metrics non-resource URL.

When you install microshift-observability, its OpenTelemetry Collector uses the openshift-observability-client certificate to scrape these endpoints. That identity also has GET /metrics permission for metrics-server. For another scraper, use a trusted client certificate for node-exporter and kube-state-metrics. Grant RBAC for service discovery, the resource metrics API, or the metrics-server /metrics only when needed.

Grant metrics scraping permissions only to trusted monitoring components. Avoid using cluster-admin credentials for scrapers.

Transport security

Exporter Services use OpenShift Container Platform service serving certificates. The kube-rbac-proxy sidecars for node-exporter and kube-state-metrics also require client certificate validation against the cluster metrics-client-ca bundle.

When you configure a scraper or forwarder, verify TLS connections to exporter endpoints and trust the service CA or the CA bundle that MicroShift provides. Do not disable TLS verification for production deployments.

Network exposure

By default, enhanced metrics endpoints are intended for in-cluster access through Kubernetes Services.

node-exporter host exposure

The node-exporter DaemonSet uses hostNetwork and publishes port 9100 on the host through kube-rbac-proxy. Network policies do not apply to pods that use host networking. Restrict host-level network access with firewalld or other host firewall controls if untrusted networks can reach the MicroShift node.

metrics-server and kube-state-metrics

These components expose HTTPS endpoints through cluster Services. Limit which namespaces and workloads can reach the openshift-monitoring namespace by using NetworkPolicy objects where appropriate.

Remote scraping

If you forward metrics to a central observability platform, secure the path between the edge node and the remote endpoint. Use encrypted transport, authenticate the collector, and protect stored metrics with access controls that match the sensitivity of the exported data.

Hardening recommendations

Use the following practices to reduce risk when you enable enhanced metrics:

  • Enable only the exporters that your monitoring workflow requires.

  • Remove enhanced metrics RPM packages when you no longer need the exporters.

  • Limit access to trusted client certificates for node-exporter and kube-state-metrics. Grant only the RBAC permissions needed for service discovery, the metrics-server /metrics, or the [metrics.k8s.io](http://metrics.k8s.io/) API.

  • Configure host and cluster network controls to limit access to exporter Services and to the node-exporter host port.

  • Review kube-state-metrics collector configuration before enabling additional custom resource metrics.

  • Treat forwarded metrics with the same confidentiality requirements as the source cluster, especially when edge nodes operate in untrusted or shared networks.

You are responsible for securing scrapers, remote endpoints, and any long-term storage for metrics that you collect outside the cluster.

Enhanced metrics configuration reference

Learn about the RPM packages, deployed resources, endpoints, and configuration parameters for enhanced metrics in MicroShift.

Optional RPM packages

Table 1. Enhanced metrics RPM packages table
Parameter Description

microshift-metrics-node-exporter

Deploys node-exporter as a DaemonSet and exposes node hardware and operating system metrics.

microshift-metrics-server

Deploys metrics-server and registers the Kubernetes metrics.k8s.io API.

microshift-metrics-kube-state

Deploys kube-state-metrics and exposes Kubernetes object state metrics.

microshift-metrics-node-exporter-release-info

Contains image reference JSON files for offline image builds and ostree deployments of node-exporter.

microshift-metrics-server-release-info

Contains image reference JSON files for offline image builds and ostree deployments of metrics-server.

microshift-metrics-kube-state-release-info

Contains image reference JSON files for offline image builds and ostree deployments of kube-state-metrics.

Deployment and endpoints

Each enhanced metrics RPM deploys resources into the openshift-monitoring namespace.

Table 2. Enhanced metrics deployment and endpoints table
Parameter Description

node-exporter.workload

DaemonSet node-exporter.

node-exporter.configurationObjects

Includes ConfigMap/node-exporter-accelerators-collector-config, Secret/node-exporter-kube-rbac-proxy-config, and Service/node-exporter.

node-exporter.endpoint

Service node-exporter on port 9100 (https). The exporter listens on 127.0.0.1:9101 inside the pod, and kube-rbac-proxy serves HTTPS on the node host network.

metrics-server.workload

Deployment metrics-server.

metrics-server.configurationObjects

Includes ConfigMap/metrics-server-audit-profiles, Service/metrics-server, and APIService/v1beta1.metrics.k8s.io.

metrics-server.endpoint

Service metrics-server on port 443 (https). The pod serves HTTPS on port 10250.

kube-state-metrics.workload

Deployment kube-state-metrics.

kube-state-metrics.configurationObjects

Includes ConfigMap/kube-state-metrics-custom-resource-state-configmap, Secret/kube-state-metrics-kube-rbac-proxy-config, and Service/kube-state-metrics.

kube-state-metrics.endpoint.https-main

Service kube-state-metrics on port 8443 (https-main). The main exporter listens on 127.0.0.1:8081 inside the pod.

kube-state-metrics.endpoint.https-self

Service kube-state-metrics on port 9443 (https-self). The telemetry exporter listens on 127.0.0.1:8082 inside the pod.

node-exporter default collector settings

Table 3. node-exporter configuration fields definitions table
Parameter Description

--web.listen-address

Address on which the node-exporter process listens inside the pod. The default value is 127.0.0.1:9101.

--collector.cpu.info

Enables the CPU information collector. This collector is enabled by default.

--collector.textfile.directory

Directory for textfile collector metrics. The default value is /var/node_exporter/textfile.

--no-collector.wifi

Disables the WiFi collector. The WiFi collector is disabled by default.

--no-collector.btrfs

Disables the Btrfs collector. The Btrfs collector is disabled by default.

--collector.netclass.ignored-devices

Regular expression that excludes network class devices from collection. The default value is ^.*$, which excludes all devices.

--collector.netdev.device-exclude

Regular expression that excludes network devices from the netdev collector. The default value is ^.*$, which excludes all devices.

--collector.filesystem.mount-points-exclude

Regular expression that limits filesystem metrics to non-container mount points. The default value excludes /dev, /proc, /sys, and container runtime paths.

node-exporter accelerators collector ConfigMap

The node-exporter-accelerators-collector-config ConfigMap defines hardware accelerator devices that the accelerators collector can expose. The default configuration includes PCI vendor and model mappings for NVIDIA, AMD, Intel, Qualcomm, Marvell, Mellanox, and Gaudi devices.

To customize accelerator detection, edit the config.yaml key in the node-exporter-accelerators-collector-config ConfigMap object in the openshift-monitoring namespace.

The kube-state-metrics-custom-resource-state-configmap ConfigMap defines additional metrics for custom resources. The default configuration includes metrics for the following API groups:

  • autoscaling.k8s.io/v1 VerticalPodAutoscaler

  • gateway.networking.k8s.io/v1 GatewayClass

  • gateway.networking.k8s.io/v1 Gateway

To add or change custom resource metrics, edit the custom-resource-state-configmap.yaml key in the kube-state-metrics-custom-resource-state-configmap ConfigMap.

metrics-server configuration

Table 6. metrics-server configuration fields definitions table
Parameter Description

--secure-port

Port on which metrics-server serves HTTPS inside the pod. The default value is 10250.

--metric-resolution

Interval at which metrics are refreshed from kubelets. The default value is 15s.

--kubelet-preferred-address-types

Address types that metrics-server uses when connecting to kubelets. The default value is InternalIP,ExternalIP,Hostname.

--kubelet-use-node-status-port

Uses the node status port reported by the kubelet. This setting is enabled by default.

--shutdown-delay-duration

Delay before metrics-server shuts down after receiving a termination signal. The default value is 150s.

--disable-http2-serving

Disables HTTP/2 for the metrics-server web server. This setting is enabled by default.

metrics-server audit profiles ConfigMap

The metrics-server-audit-profiles ConfigMap object contains Kubernetes audit policy profiles that metrics-server can reference. The default ConfigMap object defines the following profiles:

  • Metadata

  • None

  • Request

  • RequestResponse

OpenTelemetry Collector scrape configuration

When you install both a metrics RPM and the microshift-observability RPM, MicroShift installs an OpenTelemetry Collector scrape configuration drop-in file for each enabled exporter under /etc/microshift/observability/scrape.d/.

Table 7. {OTELName} scrape drop-in files table
Parameter Description

node-exporter.yaml

Installed when the microshift-metrics-node-exporter RPM is installed.

metrics-server.yaml

Installed when the microshift-metrics-server RPM is installed.

kube-state-metrics.yaml

Installed when the microshift-metrics-kube-state RPM is installed.

The drop-in files define scrape_configs entries for the OpenTelemetry Collector Prometheus receiver.

Table 8. {OTELShortName} scrape configuration fields definitions table
Parameter Description

scrape_interval

How often the collector scrapes the exporter endpoint. The default value is 10s.

scheme

Protocol used to scrape metrics. The default value is https.

tls_config.ca_file

CA certificate used to verify the exporter service certificate. The default value is /var/lib/microshift/certs/service-ca/ca.crt.

tls_config.cert_file

Client certificate used for HTTPS scrapes. The default value is /var/lib/microshift/certs/admin-kubeconfig-signer/openshift-observability-client/client.crt.

tls_config.key_file

Client private key used for HTTPS scrapes. The default value is /var/lib/microshift/certs/admin-kubeconfig-signer/openshift-observability-client/client.key.

kubernetes_sd_configs.role

Service discovery mechanism used to locate exporter endpoints. The default value is endpoints.

kubernetes_sd_configs.namespaces.names

Namespace that contains exporter Services. The default value is openshift-monitoring.

The kube-state-metrics drop-in file defines two scrape jobs:

  • kube-state-metrics for the https-main endpoint on port 8443

  • kube-state-metrics-self for the https-self endpoint on port 9443

Exporter Typical CPU usage Typical memory usage

node-exporter

~0.013 cores

~46 MiB

~0.007 cores

~80 MiB

~0.009 cores

Resource usage varies with workload activity, scrape frequency, and cluster size. Monitor your deployment after enabling exporters to validate capacity on resource-constrained edge nodes.
